## Short smoke for E10

1. Follow the [local lab setup](../e01-local-lab.md) with a dedicated owned project. Apply migrations, synchronize one exact live scope, activate Knowledge, and provision fixture Operator and Viewer accounts. Start the API/web with the worker stopped and verify `/api/health/ready` is 200 and authenticated health shows a missing or stale heartbeat.
2. Use Connections as Operator. Explicitly check Kubernetes and Prometheus once each. Record UID, receipt IDs, observed and assessed times, scoped coverage and raw freshness. Repeat one authenticated request with the original `Idempotency-Key` and expect the same ID. Verify Viewer can read the same results and has no check controls.
3. Start the owned worker. From the selected workload, create one incident and wait for a Run with an available evidence payload. Record the incident, Run and evidence IDs and hash the bytes from its `/content` endpoint. Record the Knowledge generation. Use a retained available report from the owned lab, or seed one controlled fixture with the `controlled_result` pattern in `test_health_projection.py`. Record its ID and check the report link opens that exact report. Use the seed pattern in `test_connection_operations.py` for a capacity-deferred Run and a quota-waiting Run when the owned lab has no such rows.
4. Note the original dispatch mode. Pause processing with the owned permit and verify the worker heartbeat remains fresh. Stop the owned worker and Prometheus, wait beyond the configured worker threshold (45 seconds by default) and confirm the API still reports ready. The explicit Prometheus check after cooldown should record unavailable while the earlier successful receipt remains readable.
5. While the outage continues, use only the owned Edge tab to read the saved incident, evidence, Knowledge and report as Operator and Viewer. Inspect a retained scope rejection, then follow the capacity and quota links to the exact Runs. Tab to a check and a precise workload or report link at 320 px light and 390 px dark. Verify visible focus, status announcements and no sideways overflow. Revoke the fixture Operator session and sign in again. Verify reauthentication itself adds zero check POSTs and the same saved results remain readable.
6. Restart the owned API and worker and confirm the old receipt timestamps and evidence digest still match. Restore Prometheus and run one new explicit check after cooldown. Confirm worker freshness and paused dispatch remain independent. Remove only synthetic backlog rows created for the drill before restoring the original dispatch mode. Stop only owned services and retain the persisted database and sanitized receipts for reproduction.

Re-run the [backend checks](../foundation.md) using an isolated `*_test` database, `npm test` and `npm run build` under `apps/web`, and `scripts/contracts.py` plus `scripts/test-contract-drift.py` in the backend environment. Use `test_health_projection.py`, `test_connection_checks.py`, `test_connection_operations.py`, `test_diagnosis_lifecycle.py`, `test_diagnosis_client.py` and `test_prometheus_client.py` for focused reproduction.
